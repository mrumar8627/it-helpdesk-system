# Ticket Management

## Objective

To understand how IT support tickets are created, organized, tracked, updated, and resolved.

## What Is Ticket Management?

Ticket management is the process of recording and managing user support requests from the time a problem is reported until it is resolved and closed.

A ticket provides a central record of the problem and the actions taken by the support technician.

## Creating a Ticket

A support ticket should contain enough information for the technician to understand the reported problem.

Basic ticket information can include:

- Ticket ID
- User
- Subject
- Description
- Category
- Priority
- Status
- Assigned technician
- Date and time

## Example Ticket

Ticket ID: HD-005

User: Teacher

Subject: Printer Not Working

Description:

The user cannot print documents from the office computer.

Category: Printer

Priority: Medium

Status: New

## Ticket Categories

Tickets can be organized into categories such as:

- Hardware
- Software
- Network
- Printer
- Account
- Other

Categorization helps technicians organize and identify similar problems.

## Ticket Priority

A ticket can be assigned a priority based on its impact and urgency.

Common priorities include:

- Low
- Medium
- High
- Critical

The priority should follow the organization's support guidelines.

## Ticket Status

A ticket can move through different statuses during its lifecycle.

Common statuses include:

- New
- Open
- In Progress
- Pending
- Resolved
- Closed

## Updating a Ticket

During troubleshooting, the technician should update the ticket with relevant information.

Examples:

- Troubleshooting steps
- Findings
- Error messages
- Actions taken
- Resolution
- Additional notes

## Example Update

Initial Problem:

The printer is not responding.

Troubleshooting:

1. Checked printer power.
2. Checked USB/network connection.
3. Checked printer status in Windows.
4. Printed a test page.

Finding:

The printer connection was not configured correctly.

Action:

The printer connection was corrected.

Result:

The printer successfully printed a test page.

## Assigning a Ticket

Tickets can be assigned to a technician who is responsible for investigating the issue.

Example:

Ticket: HD-005

Assigned Technician: IT Support

Status: In Progress

## Resolving a Ticket

A ticket can be marked as resolved when the reported problem has been fixed.

The resolution should describe what was done.

Example:

Resolution:

Printer connection was corrected and a successful test print was completed.

## Closing a Ticket

A ticket can be closed after:

1. The problem has been resolved.
2. The affected system has been tested.
3. The user confirms the solution when appropriate.
4. The resolution has been documented.

## Example Ticket Record

Ticket ID: HD-006

User: Staff Member

Category: Network

Priority: Medium

Status: Closed

Problem:

Computer could not access the internet.

Troubleshooting:

- Checked network cable.
- Checked IP configuration.
- Tested connectivity using ping.

Finding:

The computer did not have the expected network configuration.

Action:

Network configuration was corrected.

Result:

Internet connectivity was restored.

## Good Ticket Management Practices

An IT support technician should:

- Record accurate information.
- Use clear descriptions.
- Assign appropriate priorities.
- Keep ticket information updated.
- Document troubleshooting steps.
- Protect user information.
- Verify solutions before closing tickets.
- Avoid recording passwords or sensitive credentials.
