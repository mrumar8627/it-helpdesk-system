# Ticket Lifecycle

## Objective

To understand the different stages of an IT support ticket from creation to resolution and closure.

## What Is a Ticket Lifecycle?

The ticket lifecycle is the sequence of steps a support request follows from the time a user reports a problem until the issue is resolved and the ticket is closed.

A structured lifecycle helps IT support teams track problems and maintain accurate records.

## Main Stages

### 1. Ticket Created

The user reports a technical problem and a support ticket is created.

The ticket should contain basic information such as:

- User
- Problem description
- Date and time
- Category
- Priority

### 2. Ticket Categorized

The issue is assigned to an appropriate category.

Common categories include:

- Hardware
- Software
- Network
- Account
- Printer
- Other

Correct categorization helps organize support requests.

### 3. Priority Assigned

The technician determines how urgently the issue should be handled.

Priority may depend on:

- Number of affected users
- Impact on work
- Severity of the problem
- Availability of a workaround

### 4. Ticket Assigned

The ticket is assigned to an appropriate technician or support team.

The assigned technician becomes responsible for investigating the issue.

### 5. Investigation

The technician collects information about the problem.

This may include:

- Asking the user questions
- Checking the affected device
- Reviewing error messages
- Checking network connectivity
- Checking system settings
- Reviewing relevant logs

### 6. Troubleshooting

The technician performs appropriate troubleshooting steps.

Examples:

- Restarting a service or application
- Checking cables
- Checking network configuration
- Installing required software updates
- Checking hardware
- Reviewing system settings

All important troubleshooting actions should be documented.

### 7. Resolution

After identifying the cause, the technician applies an appropriate solution.

Example:

Problem:

The user cannot access the network printer.

Action:

The technician checks the network connection and printer configuration and corrects the required settings.

Result:

The printer becomes available to the user.

### 8. User Verification

The user should confirm that the original problem has been resolved when appropriate.

This helps ensure that the solution actually addresses the reported issue.

### 9. Ticket Closed

After the problem is resolved and verified, the ticket can be closed.

The final ticket record should include:

- Problem
- Investigation
- Findings
- Action taken
- Resolution
- Date closed
- Additional notes

## Ticket Statuses

A helpdesk system may use statuses such as:

- New
- Open
- In Progress
- Pending
- Resolved
- Closed

The exact statuses may vary between organizations.

## Example Scenario

### Problem

A teacher reports that a computer has no internet connection.

### Ticket

Ticket ID: HD-002

Category: Network

Priority: Medium

Status: New

### Investigation

The technician:

1. Checks the network cable.
2. Checks the network connection.
3. Runs `ipconfig`.
4. Tests connectivity using `ping`.
5. Reviews the IP configuration.

### Finding

The computer does not have a valid IP configuration.

### Action

The network connection is checked and the computer obtains a valid IP configuration.

### Verification

The technician tests network connectivity again.

### Result

Internet access is restored.

### Final Status

Closed

## Importance of the Ticket Lifecycle

Following a structured lifecycle helps IT support teams:

- Track support requests
- Maintain organized records
- Assign responsibilities
- Monitor unresolved issues
- Document troubleshooting
- Verify solutions
- Maintain support history
