# Ticket Priority

## Objective

To understand how IT support tickets can be prioritized based on their impact and urgency.

## What Is Ticket Priority?

Ticket priority indicates how urgently an IT support issue should be handled.

Prioritization helps support teams organize their workload and respond appropriately to important issues.

## Common Priority Levels

### Low

A low-priority issue has limited impact and does not significantly prevent the user from working.

Examples:

- Request for software information
- Minor configuration request
- General IT question

### Medium

A medium-priority issue affects a user or a small number of users but work may still continue.

Examples:

- Printer not working for one user
- Application problem with a workaround
- Minor network issue

### High

A high-priority issue significantly affects a user's work or several users.

Examples:

- Important application unavailable
- Network problem affecting multiple users
- Computer required for an important task is not working

### Critical

A critical issue has a major impact on an organization or an essential IT service.

Examples:

- Major network outage
- Important system unavailable
- Widespread IT service disruption

## Impact and Urgency

Priority can be determined by considering two important factors:

### Impact

Impact refers to how many users or systems are affected.

Examples:

- One user affected
- One department affected
- Multiple departments affected
- Entire organization affected

### Urgency

Urgency refers to how quickly the problem needs attention.

Examples:

- Can wait until normal support time
- Needs attention soon
- Requires immediate attention

## Example

### Situation 1

One employee cannot print a document, but another printer is available.

Possible priority:

**Low or Medium**

### Situation 2

The network is unavailable for an entire department.

Possible priority:

**High**

### Situation 3

The organization's main network service is unavailable.

Possible priority:

**Critical**

The exact priority should depend on the organization's support procedures.

## Priority Table

| Priority | Impact | Example |
|---|---|---|
| Low | Limited | General IT request |
| Medium | Moderate | Single-user application problem |
| High | Significant | Department network problem |
| Critical | Major | Organization-wide service outage |

## Important Consideration

Priority should be based on the actual impact and urgency of the problem.

A ticket should not automatically receive high priority simply because a user considers it urgent.

Support teams should follow their organization's priority guidelines.
